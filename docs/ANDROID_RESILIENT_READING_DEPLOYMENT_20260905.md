# Android-resilient reading deployment

Date: 2026-09-05
Status: deployed and publicly validated; A5 phone retest pending

## Outcome

Field comparison showed that all five A3 iPhone captures retained Google and
OpenAI evidence, while only two of five A5 Android captures retained both cloud
stages. One A5 capture had Google only and two had only the initial Tesseract
result. Matching images were sufficiently clear, and the missing calls had not
reached the server.

The browser now uploads a new photograph once. After the immediate Tesseract
response, it sends a small keep-alive request containing no photograph. The
server reloads the private stored source, runs missing Google and OpenAI stages
concurrently, and stores each result. Moving to another saved image or
backgrounding the browser therefore no longer cancels two large phone uploads.

The processing endpoint is idempotent: it checks durable stage evidence inside
a per-capture lock and does not call an already completed provider. Incomplete
saved captures can resume when opened, with the existing device cooldown after
a failure.

Additional corrections:

- Tesseract TSV is parsed with quoting disabled, preventing a stray recognized
  quote from swallowing all subsequent rows into one corrupt word.
- The repository-local English model is primary while Kannada remains enabled;
  conservative confidence filtering removes isolated Kannada hallucinations.
- Google paragraph words are regrouped into physical rows using geometry.
- OpenAI translations and summaries containing a non-Kannada writing system
  are filtered and the third bar is not marked ready unless Kannada output
  passes validation.
- The fourth bar remains gray; no unvalidated consensus is claimed.
